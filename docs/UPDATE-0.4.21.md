# Fukaros + Furina v0.4.21

发布日期：2026-11-11。双端配套版本为 **0.4.21**，Android versionCode 为 **25**。本版不兼容 v0.4.20 的明文连接，电脑和平板需要一起更新。

## 为什么不用 Qt TLS

投屏需要加密、完整性和双向认证。Qt 的 `QSslSocket` 依赖构建时启用的 OpenSSL，当前的 MinGW 与 Android 包并不保证带上它，测试环境也无法稳定提供证书。

因此连接在 TCP 之上使用 Monocypher 提供的 X25519、BLAKE2b 和 XChaCha20-Poly1305：

- 每台设备有一把长期身份密钥。Windows 用 DPAPI 保护私钥，Android 用 Keystore，其它系统把密钥放在仅所有者可读的文件里再加密设置中的密文。设置里不再保存明文配对码。
- 二维码或手动配对码作为一次性共享密钥混入密钥派生。不知道该密钥的人无法完成握手，也不能离线冒充已经固定的身份密钥。
- 二维码里是电脑的完整公钥，平板在握手时核对，避免只靠首次信任。
- 临时 X25519 密钥提供前向保密。握手完成后，原来的 FUR1 画面、控制和鼠标消息整帧放入加密记录，`sendVideo` 的排队逻辑没有改写。
- 独立鼠标通道不再把会话密钥直接写到网上，而是用派生密钥做加密握手。

20 位配对码来自 32 个字符（去掉容易看错的 I、O、0、1），大约 100 位熵，并限制在线尝试。这不能替代真正的口令学 PAKE 对低熵密码的保护，所以手动码必须保持这个长度，二维码则使用 256 位一次性密钥。

## 配对

1. 电脑设置中点“显示配对二维码”。二维码包含本机地址、端口 27183、一次性密钥和电脑公钥，两分钟内有效，连接成功后不能再用。
2. 平板点“扫描二维码”，用后置相机扫描。桌面模拟可以把二维码下面的文本粘贴到“二维码内容”。
3. 不能扫码时，任一端点“生成配对码”，把 20 位码输入另一端。码在 10 分钟后过期。连续失败会锁定大约 5 分钟，短时间内连接次数也有限制。
4. 扫码或输入成功后，再选择分享或获取屏幕并按开始，仍须对端同意。

Wi-Fi 监听地址必须填写本机局域网 IP，或留空时使用当前网卡地址，不再默认 `0.0.0.0`。USB 在网卡地址尚未出现时仍可能临时监听全部 IPv4，并套用同样的次数限制。

## 虚拟显示助手

安装程序改为需要管理员权限，默认目录是 Program Files。若助手程序位于用户目录或当前用户可写的位置，扩展桌面不会再对它提权，以免用户可写文件被换成高权限进程。

## 旧版本

旧端发出的第一个报文以 `FUR1` 开头。新端会断开并说明对端仍是 v1 明文协议，请同时更新到 0.4.21。新端之间的画面消息编号没有改，只是外面多了加密记录。
