# 副屏放大开关与卡顿验证

日期：2026-10-21。以下为 0.4.20 修订的已有实机验证记录；本次源码同步未重新运行测试，稳定版安装包仍为 v0.4.19。

## 实际设备与流程

Windows实际MainWindow、VirtualDisplayController、采集及编码链路，Xiaomi Pad 6 Pro实际Furina解码与显示。通过临时ADB USB转发28183→27183连接；沿用配对校验、投屏同意与扩展位置流程。1920×1200、目标60FPS，固定动画窗口，依次100%→150%→100%→150%，每段20秒。测试结束恢复移动端先前的缩放偏好并释放虚拟屏，电脑端使用隔离的测试设置，不修改正式配对参数。

修复前首段因等待位置配置尚未收到视频，排除该段；其余有效段作基线。修复后在首次视频反馈后开始分段计时，四段均有效。各段前3秒为切换恢复期，不纳入稳定平均值。因此这是有限时长的同机对照，并非同长度基准或全面性能保证。

## 切换恢复

修复前：实际开始解码的3代流共8次初始化，其中5次原因是队列溢出；共6次队列溢出事件。切换后的单秒反馈曾降到解码11FPS/显示10FPS。

修复后：4代流各初始化一次，共4次；0次队列溢出、0次因积压导致的额外初始化、0次解码异常。缩放改变仍重新绑定采集/编码并产生新流编号，切换时仍可能短暂停顿。本修订没有把它宣称为无缝切换。

原始记录保存在任务work目录：scale-ab-before.log、scale-ab-before-android.log、scale-ab-after.log、scale-ab-after-android.log；汇总scale-toggle-ab-result.json。不将本机原始运行日志自动上传。

这些数据没有测量输入到光子的绝对延迟，也不代表无线局域网、其他设备、长时间负载或所有缩放档位。不能据此承诺全场景恒定60FPS。

## 回归与复现

协议、开关保存/恢复及双端同步、双端界面和多屏布局的5项CTest测试组通过。scale_stream_smoke为需真实设备的手动硬件工具，不加入自动CTest；运行前先开启平板接收服务并设置临时USB转发。工具沿用真实同意按钮并会修改/释放专用扩展屏。

MediaCodec恢复按同步模式flush并从含编码参数的关键帧恢复，遵循[Android官方MediaCodec文档](https://developer.android.com/reference/android/media/MediaCodec)。
