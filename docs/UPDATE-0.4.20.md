# Fukaros + Furina v0.4.20

首次发布：2026-10-23；同版本覆盖更新：2026-10-26。双端配套版本仍为 **0.4.20**，Android versionCode 仍为 **24**。

## 下载与更新

在 [v0.4.20 发布页](https://github.com/HuTaoUnknow/Fukaros-Furina/releases/tag/v0.4.20) 下载 Windows x64 安装包和 Android ARM64 APK，并同时更新两端。电脑端覆盖原安装目录；安卓沿用既有签名，可直接覆盖安装，无需卸载或清除数据。发布页同时提供 `SHA256SUMS.txt`。

本次按同版本覆盖发布，原发布链接不变。此前发布包和本地修订也使用 0.4.20；请重新下载本次附件，并用最新 `SHA256SUMS.txt` 区分构建。

## Windows 标题栏修复（2026-10-26）

- 修复退出全屏后最小化、最大化、关闭按钮及窗口边框消失。问题由 Qt 在退出全屏时重新应用此前缓存的无边框样式引起。
- 先退出全屏状态，再恢复原始窗口标志、普通／最大化状态和窗口位置；支持最小化恢复、隐藏后恢复及重复切换。
- 原生窗口测试直接核对 Windows 标题栏、系统菜单和可缩放边框，避免只检查 Qt 内部标志而漏掉问题。
- 双端从同一份正式源码构建；本次逻辑修改仅影响 Windows，安卓保持既有功能和数据兼容。

## 投屏方向记忆

- 两端分别保存“分享屏幕／获取屏幕”的选择，关闭并重新打开后恢复，同时显示对应的复制／扩展区域。
- 改变方向、正常退出及窗口销毁前写入；安卓进入后台时额外保存，覆盖系统可能不运行 C++ 析构的进程回收情况。
- 方向与连接设置分开保存，后台记录不会接受设置弹窗中尚未保存的修改。没有记录或值异常时使用原有默认方向。
- 恢复选择不会自动开始投屏；仍须手动开始并得到对端同意，投屏期间继续遵守方向锁定。

## 副屏放大

- 双端“独立映射鼠标”下方提供“副屏放大”开关，默认开启，比例默认 150%；支持 100%、125%、150%、175%、200%、225%、250%、300%。
- 关闭时应用 100%，保留原先所选比例；再次开启后恢复。开关与比例立即保存、双端同步，可在投屏期间调整。
- 仅对电脑向移动端扩展时的专用虚拟显示源应用 Windows 显示 DPI，不改变主屏比例，保持 1920×1200／1200×1920 的完整桌面像素。复制和反向投屏时保存偏好，待下次扩展使用。
- 系统不支持指定档位时回传实际比例；部分旧应用需要重新打开窗口才能跟随 DPI。切换比例会重新绑定采集，可能短暂停顿。
- 使用 screen-scale-v2 能力协商同步开关；旧 v1 对端只接收有效比例，关闭对应 100%，避免不兼容长度的数据包。

## 解码与独立鼠标修复

- 安卓解码队列积压时合并恢复请求，在解码线程执行一次 flush 后从携带编码参数的关键帧恢复，避免重复关闭并重建解码器。
- 初始化阶段允许有限预热缓冲；稳定后继续限制队列长度。流换代、Surface 更换及实际解码错误仍可重建。
- 独立鼠标通道在连接完成和认证就绪后设置 LowDelayOption，覆盖初次连接及重连，修复原生 socket 创建前设置未生效的问题。
- 副屏鼠标移速倍率仍为主屏的 0.25–4 倍，双端同步，主屏系统鼠标速率保持不变。

## 构建与验证

本次覆盖包从正式源码构建，不包含临时鼠标观测代码。Windows Release 构建完成，6 个原生标题栏场景及双端界面回归通过；Android ARM64 Release 重新构建，APK 签名、既有证书一致性及 16 KiB 对齐校验通过。2026-10-23 的协议、连接、双端界面、缩放设置五组回归属于此前发布验证。

本次不重新开展真实设备投屏或性能测试。已有缩放对照与鼠标低延迟配置检查分别见 [缩放对照记录](VALIDATION-SCALE-TOGGLE.md) 和 [独立鼠标检查](VALIDATION-CURSOR-NODELAY.md)，其数据属于此前验证。目标 60 FPS，实际帧率和延迟仍受设备、网络及负载影响。完整范围见 [发布验证](VALIDATION.md)。
