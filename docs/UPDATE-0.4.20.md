# Fukaros + Furina 0.4.20（开发版源码同步）

2026-10-21：主分支同步双端 0.4.20 功能与修复源码，Android versionCode 24。当前稳定版安装包仍为 v0.4.19；本次不创建新 Release 或安装包下载链接。

## 副屏可读性

双端“通用设置”现在提供两项独立设置：

- **副屏鼠标移速倍率**：主屏鼠标系统速率不变，副屏按 0.25—4 倍调整。
- **副屏屏幕放大比例**：默认 **150%**；提供 100%、125%、150%、175%、200%、225%、250%、300%。100% 恢复原始大小，实际可用档位取决于 Windows。

放大比例应用在电脑向移动端扩展时的专用虚拟显示源，通过 Windows 显示 DPI 放大字体和控件。保持 1920×1200 / 1200×1920 的桌面像素、不裁切，不影响主屏 DPI；与视频分辨率选择相互独立。复制和移动端向电脑分享时，仅保存这项设置，等下次扩展应用。

两项都即时保存、双端同步，投屏期间可调整。扩展启动先应用比例、等待 DPI 事件稳定后绑定采集；运行中更新比例后重新绑定采集和鼠标显示器。Windows 不支持指定档位时，保留并回传实际比例，在调试日志说明原因。少数旧应用需要重新打开窗口才能跟随 DPI。

## 兼容与实现

- Windows DPI 兼容边界位于 `Fukaros/core/display/display_scale.c`，只接受已取得且未与物理目标共用的虚拟显示源；不写全局 DPI 或注册表。
- 当前 Windows SDK 没有公开逐显示源 DPI 写入结构，因此兼容实现对私有设备信息包的大小、范围、源身份及返回值做校验。系统不支持时明确报告，不改变主屏或静默降低画质。
- 共用策略在 `core/protocol/screen_scale.c`，同步偏好在 `core/settings/screen_scale_settings.cpp`。
- 新增可选消息 17。先使用旧版可解析的状态消息协商能力，仅在双方声明支持后发送，避免连接旧端时发送未知消息。
- 缩放菜单复用现有移动端触控弹层；为表单补齐显式编译依赖，避免增量构建沿用旧界面。
- 两端源码版本统一 0.4.20，Android versionCode 24。GitHub 最新稳定版安装包仍是 0.4.19。

## 本地修订：副屏放大开关与实机卡顿排查（2026-10-21）

- 双端在“独立映射鼠标”下一行增加“副屏放大”，默认开启以保留原版行为。关闭后应用 100%，比例选择暂不可用且保留原值；重新开启恢复所选比例。开关与比例一起保存、双端同步。
- 通过 screen-scale-v2 能力协商同步开关；旧 v1 对端仅接收有效比例（关闭为100%），不发送不兼容长度的数据包。相同比例的同步版本更新不会重复请求应用。
- 安卓待解码队列溢出不再排队关闭解码器；合并恢复请求，在解码线程一次 flush 后从携带 SPS/PPS 的关键帧恢复。仅初始化阶段允许最多16帧及250毫秒预热缓冲，稳定后仍使用6帧限制。尺寸/流换代、Surface更换与真正解码错误仍允许重建。
- 增加 FurinaVideo 日志：重建原因、流编号、队列峰值、解码及显示帧率。没有隐藏原有初始化日志。
- 实测方法、数据及限制见 [缩放对照验证](VALIDATION-SCALE-TOGGLE.md)。双端保持 0.4.20 修订。

## 独立鼠标低延迟修复

- Qt 客户端原生 socket 尚未创建时设置 LowDelayOption 不能保证生效。现在在连接完成和认证就绪时设置，覆盖初次连接和重连；接收端也保证开启。
- 既有专项回归覆盖认证、最新坐标合并、两侧低延迟选项及视频通道阻塞期间的独立传输，记录见 [独立鼠标检查](VALIDATION-CURSOR-NODELAY.md)。
